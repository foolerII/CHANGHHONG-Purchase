# 预计返利管理 PRD

> 与《预计返利闭环管理方案 V1.2》保持一致。字段和规则以 `00-facts.md` 为准。

## 目标

让采购管理人员在采购订单管理平台内完成预计返利的闭环：查询合同预计返利、将待关联合同关联至返利或到款、追踪已关联记录与返利底表余额，并在超期未关联时收到预警。

## 用户与权限

| 角色 / 状态 | 可执行操作 |
|---|---|
| `read` | 查看列表与详情、导出 |
| `readWrit` | 查看、编辑待关联合同、导出模板、批量导入 |
| 采购经理 | 在已关联合同上按单条记录解锁 |
| 超级管理员 | 可见返利数据底表 |

行权限统一按产品线控制。

## 信息架构

预计返利管理下包含四个菜单：待关联返利合同、已关联返利合同、已关联返利明细、返利数据底表。

## 数据粒度

全部列表按「合同号 + 核算大类 + 币种」展示，一个组合为一行，下称合同行。同一合同有多个核算大类或币种含预计返利时展示多行。

## 核心流程

1. 项目管理平台同步已审批完成、含预计返利的合同，进入待关联列表。
2. 用户按日期、合同、客户、核算大类等条件查询。
3. 点击编辑进入整页编辑视图，在表头选择关联方式。
4. 关联返利：点击选择返利打开弹框，按核算大类或产品线筛选剩余可关联金额大于 0 的返利，支持多选，逐行填写本次关联金额。
5. 关联到款：系统按到款系统挑款记录自动带出到款行，用户逐行填写关联金额，填 0 表示取消该笔关联。
6. 保存时校验返利额度、挑款额度和合同额度，通过后提交。
7. 合同剩余返利金额大于 0 的仍停留在待关联，等于 0 的移入已关联。
8. 已关联合同需要调整时，由采购经理按单条记录解锁，金额释放后合同回到待关联。
9. 外部系统数据变动时系统自动释放关联并发送通知邮件，合同自动回到待关联。

## 批量导入

- 模板字段：合同号、关联方式、返利编码、关联到款ID、本次关联金额、核算大类、币种。
- 关联返利为新增记录；关联到款按到款ID逐条替换，未出现在文件中的到款ID不做处理。
- 任一行校验不通过整批失败，错误提示定位到具体行号。
- 金额最多两位小数，超过两位直接报错。
- 逐行校验通过后再按导入后的最终状态做合并校验。

## 预警邮件

到期前 4 周开始每周推送，到期后继续每周推送 4 次，第 5 至 7 周加送事业部总，之后停止。推送条件是合同出库金额大于 0 且合同剩余返利金额大于 0。

## 原型范围

- 四个列表页及查询、导出、导入交互。
- 待关联的整页详情与整页编辑，含关联方式切换、返利选择弹框、增删行和完整保存校验。
- 已关联的整页详情（有效 / 失效筛选）与整页解锁。
- 全部数据来自 `prototype/mock-data.js`，不调用生产接口。
- 批量导入按方案口径真实执行逐行校验与合并校验，通过后真实写入演示数据。
- 演示模式开关：开启时显示角色切换与字段口径说明号，用于评审与开发沟通；关闭后即为上线形态。

## 不在原型范围内

- 定时同步、邮件推送、数据迁移等后台能力，仅在文档中描述。
- 分页、排序、字典接口等平台通用能力，沿用现有实现。
